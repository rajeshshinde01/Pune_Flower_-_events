# Build and deploy Pune Flower & Event Studio

This website is built with React, Vinext, and a Cloudflare Worker-compatible
runtime. It should be hosted on a platform that supports Cloudflare Workers or
the approved Sites hosting workflow. It is not deployed by uploading a plain
`dist/` folder to a basic shared web host.

## Before you begin

Install the following on the build computer:

- Node.js 22 LTS or later
- npm
- Git, if you are downloading the project from a repository

Confirm the tools are installed:

```sh
node --version
npm --version
```

## Get the project

Clone the repository, or copy the full `pune-flower-event-studio` folder to the
build computer. Then open a terminal in that folder:

```sh
cd pune-flower-event-studio
```

## Install dependencies

```sh
npm install
```

## Run locally

Start the local development website:

```sh
npm run dev
```

Open the local address printed in the terminal. Confirm the homepage, gallery,
occasion finder, enquiry form, WhatsApp links, map, contact details, and mobile
layout before publishing.

Stop the local server with `Ctrl+C` when finished.

## Build and verify

Create a production build:

```sh
npm run build
```

Then run the automated rendered-page check:

```sh
npm test
```

The build output is prepared for a Worker-compatible deployment. Do not edit
generated build output directly; make changes in `app/` or `public/`, then
build again.

## Deploy using the approved Sites workflow

This project is already connected to the approved Sites hosting service. For a
normal update:

1. Make the required website changes.
2. Run `npm run build` and `npm test`.
3. Commit the source changes to Git.
4. Use the approved Sites publishing workflow to package the matching source
   commit and deploy it.
5. Confirm the deployment succeeded, then open the private live URL and test
   the published website on desktop and mobile.

The current hosting identity is declared in `.openai/hosting.json`. Keep that
file in the project and do not replace its project ID when updating the existing
website.

## Deploy to another approved platform

Use a provider that supports the Cloudflare Workers runtime. Configure it to:

- install dependencies with `npm install`
- build the website with `npm run build`
- deploy the Worker build output generated by Vinext

The exact publish command and credential setup depend on the chosen provider.
Keep deployment tokens, domain credentials, and any future API keys in the
provider's secret manager, never in source code or Git.

## Update checklist

Before each publishing update:

- Verify phone number, WhatsApp links, address, map, and business hours.
- Confirm every new photo is owned or authorised for use.
- Use only genuine customer feedback and ratings.
- Test enquiry fields, selected package information, and WhatsApp message
  content.
- Review the site at phone, tablet, laptop, and large desktop widths.
- Keep the last successful source commit available as a rollback point.

## Roll back an update

If a release has a problem:

1. Identify the last known-good Git commit or saved hosting version.
2. Redeploy that exact source version through the approved hosting workflow.
3. Recheck the homepage, enquiry form, WhatsApp links, and mobile layout.
4. Record what was corrected before attempting the next release.
